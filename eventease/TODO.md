# EventEase delivery outcomes

- [ ] **Premium home and discovery** — Build a distinctive premium EventEase home page with a navigation bar for Explore, AI Planner, My Events and Profile; the heading “Every Occasion. Beautifully Planned.”; location-aware event search; trending, personalized and curated sections; categories; a featured AI-planner section; statistics and footer. Support event discovery across festivals, birthdays, weddings, college fests, hackathons, concerts, workshops, conferences, corporate events, trips, private parties and community gatherings. Search by event name, category, city, date and keywords. Filter by event type, date range, location, price and online/in-person format. Sort by date, relevance and popularity where supported by real data. Show event details including description, date, venue, price, organizer and available verified links. Support bookmarks for signed-in users, share through native share or a copy-link fallback, and useful empty states. Clearly distinguish verified external listings, curated information and user-created events. Do not pretend to have a live global event database; keep provider integration behind a service interface and label curated seed records when no event API is configured.

- [x] **Authentication, database and private data** — Use MongoDB Atlas with Mongoose for users, events, saved events, event plans, guest lists, budgets, expenses, tasks and related data. Include useful safe, repeatable seed data; never seed real personal information or represent samples as live listings. Provide secure registration/login with bcrypt password hashing, secure session/JWT handling, logout and session expiry. Protect private APIs and validate authorization for every user-owned resource. Never hardcode a successful authentication state. Do not trust browser-submitted IDs, prices, roles or ownership values. Save signed-in user data in MongoDB, not permanent localStorage. If MongoDB configuration is missing, give a useful setup error rather than crashing or pretending to persist.

- [x] **AI event-planner wizard** — Collect event type/occasion; city, country or online format; date and duration; guest count; budget and currency; preferred style/theme and atmosphere; indoor/outdoor preference; food and dietary requirements; decoration; entertainment and activity preferences; accessibility needs; and additional instructions. Generate a structured plan with personalized theme/concept and color palette, venue requirements and selection criteria, food and beverage plan, activities, time-based schedule, categorized estimated costs, guest checklist, shopping/preparation checklist, preparation timeline counted back from the date, contingency suggestions, and sustainable/budget alternatives. Display polished editable sections; allow edit, section regeneration, checklist completion and save. Ask Gemini for structured JSON and validate the response and all inputs on the backend. Never render raw AI output as trusted HTML. Validate numeric budgets, guest counts and dates. Label prices estimates, not quotes. If Gemini/API quota/model fails, explain that clearly, offer a functional non-AI fallback, and retain the user's inputs for retry.

- [x] **Festivals and seasons** — Provide festival discovery for Diwali, Holi, Navratri, Durga Puja, Eid, Christmas and regional celebrations. Include dates and confidence labels, cultural context, preparation, decor, food and celebration suggestions, location-aware suggestions when location is supplied, festival-based planning templates, a calendar and an upcoming-celebrations countdown. Support movable festival dates without hardcoding the same date every year and distinguish confirmed from approximate/unverified dates.

- [x] **Budget and expense manager** — Let users set a total event budget and currency; divide it into venue, food, decoration, entertainment, travel, gifts and miscellaneous. Add, edit and delete expenses. Compare estimated costs against actual expenses and show total planned spending, actual spending and remaining budget. Add an accessible lightweight chart and warnings when expenses exceed the budget. Format selected currencies, but do not claim live conversion without an exchange-rate service.

- [x] **Guests, RSVPs and invitations** — Let users add, edit and remove guests; store name, supplied contact details, RSVP status, dietary notes and permitted special requirements; filter guests by invitation/attendance status; show invited, confirmed, declined and pending counts; export guest lists as CSV; and generate invitation text that a user can copy or share. Do not send invitations without a configured email or messaging service.

- [x] **Task management and agenda** — Let users create tasks with deadlines, priorities and categories; display an event-day agenda with start and end times; mark tasks complete; show overdue and upcoming tasks; save all changes to the database for authenticated users; and provide useful loading, error and empty states.

- [x] **Venue/vendor discovery** — Create a provider integration layer for venue, catering, photography, decoration and entertainment searches. Support city, capacity, price range and category filters when actual provider data exists. Distinguish real provider listings from AI-generated recommendations and only provide booking/contact links when available and verified. When no venue API is configured, provide venue-selection criteria, a comparison workspace and manually entered venue options. Never fabricate business listings, availability, reviews or contact information.

- [ ] **Dashboard, bookmarks and account utilities** — Provide a dashboard overview of saved events, upcoming celebrations, active plans, tasks and budgets; recently viewed/bookmarked events; quick actions to create a plan, explore festivals, manage guests or add expenses; profile and account settings; persistent user-owned plans; and useful new/returning-user states. Where feasible, add event templates, responsive calendar, print/download plan summaries, invitation/caption/description writing and PWA support.

- [x] **Design, accessibility and complete interactions** — Use HTML5, CSS3 design tokens, responsive modern effects/animations, modular vanilla ES6+ JavaScript, Node.js/Express REST APIs, Mongoose and the official supported Google Gemini SDK. Do not use React, Next.js or a frontend framework. Use Lucide icons or Font Awesome and quality event photography with fallbacks. Keep a recognizable human-crafted premium event-tech identity, editorial layout, deliberate whitespace, clear hierarchy, refined cards/dialogs/filters/toasts/empty states and mobile-first behavior. Ensure every visible button/form/menu/filter/tab/modal works; keyboard navigation, visible focus, accessible contrast and reduced-motion are supported; give helpful errors/loading/field validation/confirmation on destructive actions. Do not leave placeholder buttons, fake live API responses, exposed secrets, hardcoded auth, silent errors, dead links, pseudo-code or one enormous source file.

- [x] **Security, runtime, documentation and deployment** — Serve frontend and API from one Express application and provide health checks, consistent JSON responses, useful HTTP codes, input validation, pagination where appropriate, centralized errors, auth/AI rate limits, appropriate CORS, Helmet headers, bounded request size, ownership checks, secure production cookies/sessions, production static serving and meaningful missing-config behavior. Keep secrets backend-only; never expose secrets to browser files, source maps, responses or logs. Provide production start and development/test/seed npm scripts, a lockfile, a supported Node.js LTS toolchain and compatible packages, root `.env.example`, ignored local `.env` with blank placeholders and `.gitignore` rules. README must cover prerequisites, installation, configuration, local development, tests, MongoDB Atlas, Gemini key setup, Render environment/build/start/health configuration, security, optional integrations and troubleshooting. Do not ask for or embed the user's real API key.

- [x] **Running preview and source ZIP** — Implement actual structured source files, not only a code listing. Start the Express app on the configured Manus preview port and verify the running home page and static route manifest. After the running preview is available, provide a downloadable structured source ZIP for local extraction. Exclude `.env`, credentials, dependencies, Git metadata and generated runtime/build artifacts. Do not claim checks passed or deployment succeeded unless verified.

## Release notes

- The preview uses clearly labeled curated sample events because no live event provider is configured. Its “Most popular” sorting option appears only when a configured provider returns real popularity scores.
- The two still-open outcomes above are the user-specific recommendation layer based on preferences/recent browsing and the dashboard's “recently viewed” list. These are not represented as implemented.
- This is a running Manus preview, not a public production deployment. MongoDB Atlas persistence, authenticated accounts, Gemini generation and external event/venue listings require the user's own backend environment configuration.
